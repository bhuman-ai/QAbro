# Public Documentation

## Job

Help a first-time customer connect Before Users Do to a coding agent and understand the three available testing modes without reading internal tool documentation.

## Product Archetype

Single-column developer-tool quickstart. The page borrows the progressive disclosure and copy-first setup grammar of strong API documentation while keeping the existing Before Users Do public-site brand.

## Primary Action

Create an MCP key and connect the hosted Before Users Do MCP endpoint.

## Public Flow

1. Open `/docs` without signing in.
2. Choose `Get MCP key`; sign in or create an account if needed.
3. Land directly on focused MCP key setup without creating a brand or connecting GitHub first.
4. Copy either the Codex TOML or generic JSON MCP configuration.
5. Ask the coding agent for one of three outcomes: AI QA, owner self-review, or a real human tester.
6. Read what evidence comes back and how safe access is handled.

## Information Budget

- One quick start.
- One connection snippet at a time.
- Three plainly named test modes.
- One evidence summary.
- Advanced service-token, self-hosting, raw tool, and operator details stay in `MCP_QA_SERVER.md`.

## Responsive Contract

- No sidebar.
- One content column on small screens.
- Configuration blocks scroll horizontally without widening the page.
- Primary actions remain text-labeled and at least 44px tall.
- Navigation links collapse before they compete with the logo and MCP-key action.

## Content Contract

- Say “AI tests it,” “You test it,” and “A real person tests it.”
- Do not require customers to know MCP tool names.
- State that a reachable URL is normally the only missing input after an agent finishes work.
- State that human-test requests are created through MCP without another form.
- Keep brand setup, repository setup, and dashboard exploration outside the first MCP connection path.
- Never describe an inconclusive result as a pass.
