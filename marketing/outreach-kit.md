# Founder outreach kit

## Qualification

Contact a builder only when all of these are true:

1. They publicly shipped or materially updated a reachable web app in the last 30 days.
2. They explicitly use an AI coding workflow or ask for feedback on the shipped product.
3. A concrete, user-visible flow can be named from their post or public site.
4. The same public platform permits a reply or direct message.

Do not scrape email addresses, invent familiarity, claim the product has been tested already, or send an automated follow-up.

## Message variants

### Pain or cost

> Saw you just shipped **[specific flow]** in **[product]**. The awkward bugs tend to show up after the coding agent says it’s done—especially across browser state, console errors, and the full click path. I built Before Users Do so the agent can run that QA pass and get fix-ready evidence back. If you’re open to it, try it on that one flow: **[tracked link]**.

### Desired outcome

> **[Specific flow]** looks like a strong candidate for a quick pre-user QA pass. Before Users Do lets your coding agent test the live flow and bring screenshots plus fix-ready findings back into the same workflow. I’d start with only that flow: **[tracked link]**.

### Mechanism or proof

> I noticed you built **[product]** with **[tool/workflow]**. Before Users Do adds a hosted QA MCP plus a companion skill, so the agent can drive the browser, capture console/network evidence, and return a report it can fix from. The install path is here if you want to test **[specific flow]**: **[tracked link]**.

## Personalization checklist

- Name the product and one real flow.
- Use exactly one message angle.
- Match the link’s `utm_content` to `pain`, `outcome`, or `mechanism`.
- Make no performance, customer-count, or outcome claim.
- Send once. Follow up only if the builder replies.
